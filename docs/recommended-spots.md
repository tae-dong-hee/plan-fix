# 메인 인기 장소 추천 후보

메인 화면의 `강원도의 인기 장소`는 강원특별자치도 18개 시군에서 3곳씩 고른 54개 명소를 추천 후보로 사용한다. 재진입과 새로고침마다 이 후보 안에서 다시 선택한다.

이 목록은 지역을 고르게 소개하기 위한 서비스 편집 목록이다. 공식 인기 순위나 관광공사가 선정한 상위 54곳이라는 의미는 아니다. 음식점·카페·숙박업소와 기간이 정해진 축제 대신 관광지, 문화시설, 상설 탐방 명소를 중심으로 구성했다.

## 확인 범위

- 확인일: 2026-09-19.
- 운영 공개 목록 API `GET /api/v1/spots?region=51&keyword=…&size=…`에서 후보의 정확한 이름, 시군, 분류와 썸네일 URL 유무를 확인했다.
- 54곳 모두 `region=51`이고 비어 있지 않은 썸네일 URL을 가지고 있었다. 이미지 파일별 HTTP 응답이나 실제 이미지 렌더링까지 확인한 결과는 아니다.
- 아래 `spotId`는 확인 당시 운영 데이터를 대조하기 위한 값이다. 환경별 DB 식별자는 달라질 수 있으므로 추천 후보의 식별 기준으로 하드코딩하지 않는다.
- 공개 API에는 원천 TourAPI의 `contentId`가 노출되지 않으므로, 추천 후보는 `region`, `sigungu`, 수집된 정확한 `title`로 식별한다.

## API와 화면 동작

- 메인 추천 목록은 `GET /api/v1/spots/recommended`에서 제공한다.
- `region` 기본값은 `51`이며 빈 문자열도 `51`로 취급한다. 선택적인 `sigungu`로 시군을 제한하며, 빈 값이면 강원 전체 후보를 사용한다. 다른 광역 지역이나 등록되지 않은 시군은 빈 목록을 반환한다.
- `size` 기본값은 `20`, 허용 범위는 `1`부터 `100`까지다. 범위를 벗어나면 잘못된 요청으로 처리한다. 응답은 기존 `SpotResponse` 구조를 사용하며 `offset=0`, `size=요청값`, `totalCount=현재 조회 가능한 고유 후보 수`다.
- 후보 카탈로그의 정확한 `title`·`sigungu`와 일치하고, `region=51`, `source=TOUR_API`, `status=ACTIVE`인 수집 데이터를 선택한다. 동일한 장소의 중복 수집 레코드는 가장 작은 DB `spotId` 하나로 정리한다.
- 누락·비활성·미수집 후보는 건너뛰고, 일반 음식점·숙박업소나 인기순 장소로 채우지 않는다. 사용 가능한 후보가 없으면 `items=[]`를 반환한다. 카탈로그 자체가 없거나 형식이 잘못된 경우에는 애플리케이션 시작 시 실패하도록 한다.
- 썸네일 URL의 존재를 별도 추천 조건으로 삼지는 않는다. 기존 `SpotThumbnailResolver`가 대표 사진과 상세 사진을 확인하고, 사용할 사진이 없으면 화면의 기존 대체 표현을 사용한다. 좋아요 정보도 기존 일괄 조회 경로를 따른다.
- 현재 조회 가능한 후보 전체를 섞은 뒤 `min(size, 후보 수)`만큼 반환한다. 18개 시군에 3개씩 후보를 두지만, 한 번의 결과에 모든 시군이 포함되도록 강제하는 추첨 방식은 아니다.
- 메인 화면은 `region=51`, `size=20`으로 요청하며 선택 지역이 있으면 `sigungu`를 추가한다. 화면 재진입·새로고침·선택 지역 변경·재시도 시 새로운 목록을 요청한다. 화면 안의 좋아요 상태 변경은 새로운 추천 추첨의 계기로 삼지 않는다.
- 브라우저 요청은 `cache: no-store`, API 응답은 `Cache-Control: no-store`를 사용한다.
- 기존 검색·인기순 목록 API `GET /api/v1/spots?sort=popular`와 더보기 목록의 인기순 의미는 유지한다.
- 무작위 선택이므로 서로 다른 요청에 같은 장소가 다시 나올 수 있다. 이전 결과와 반드시 다른 목록이라는 보장은 하지 않는다.

## 유지보수

1. 후보 추가·교체 전 목록 API에서 `region=51`, `sigungu`, 정확한 `title`, 썸네일 유무를 확인한다. 동명의 음식점·숙박업소, 한 명소의 세부 시설이나 중복 수집 레코드를 혼동하지 않는다.
2. 수집 데이터의 명칭이 바뀌면 추천 카탈로그와 이 문서의 이름을 함께 변경한다. 공백, 괄호, 가운데점도 정확히 맞춰야 한다. 예를 들어 `경포해변`이 아닌 `경포해수욕장`, `통일전망대`가 아닌 `고성 통일전망타워`를 사용한다.
3. 추천 카탈로그의 코드를 바꾸지 않은 채 이 문서의 감사용 `spotId`만 변경해도 실제 추천 대상은 바뀌지 않는다. 운영 식별자를 카탈로그 키로 옮겨 쓰지 않는다.
4. 시군별 후보 수와 지역 분포를 확인한다. 기간 한정 행사나 폐업·휴관 정보가 있는 시설을 추가할 때에는 별도 운영 검토가 필요하다.
5. 메인 재진입·새로고침·지역 변경, 후보 부족, 썸네일 누락, 좋아요 연동을 검증한다. 이미지 URL이 있다고 실제 이미지 응답까지 정상인 것은 아니므로 화면 검증에서도 사진 로딩을 확인한다.
