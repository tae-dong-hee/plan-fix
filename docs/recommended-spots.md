# 강원도 인기 장소 추천 후보

2026-09-19 기준 강원특별자치도 18개 시군에서 **20곳씩 총 360곳**을 편집 선정했다. 기존 54곳을 모두 유지하고 306곳을 추가했다. 관광명소에 카페·음식점·전통시장·문화시설·레포츠를 함께 구성했다.

지역마다 웹 검색으로 공식 관광 포털, 한국관광공사 여행기사·장소 소개 등을 확인한 뒤 실제 운영 데이터와 대조했다. 공식 인기 순위나 방문객 수 상위 20위라는 의미는 아니다. 영업시간·가격·입장 및 예약 조건은 변동될 수 있으며 이 선정의 검증 대상이 아니다.

## 데이터와 S3

- 실행 카탈로그: `backend/src/main/resources/recommended-gangwon-spots.json`
- [360곳의 출처·분류·주소·좌표·TourAPI contentId](assets/recommended-spot-sources.json)
- S3: `s3://planfix-bucket-975050156432-ap-northeast-2-an/catalogs/recommended-spots/2026-09-19-v1/`
- `catalog.json`은 실행 카탈로그와 바이트 단위로 같고, `sources.json`은 검수 메타데이터다. `places/{sigungu}/{contentId}.json`에 장소별 레코드 360개를 저장한다(총 362객체).
- 객체는 비공개이며 같은 버전의 다른 내용으로 덮어쓰지 않는다. 업로드 후 전 객체를 내려받아 내용·SHA-256·Content-Type을 역검증한다.
- 서버는 배포에 포함된 동일 카탈로그를 읽는다. S3는 검수 데이터 보관본이며 실행 중 S3 변경으로 추천 목록이 바뀌지 않는다. 변경은 새 카탈로그 버전과 배포로 반영한다.
- 저장 대상은 **장소 데이터와 기존 사진 URL**이다. 이번 작업에서 외부 이미지 파일을 S3에 복제하지 않았다.

## 확인 결과

- 360곳 모두 공개 상세 API HTTP 200, 이름·지역·분류·주소·좌표 일치, ID/contentId 중복 없음, 시군별 정확히 20곳.
- 기존 54곳을 제외하지 않았으며 전체 후보가 `region=51`, `source=TOUR_API`, `status=ACTIVE`인 운영 레코드에 연결됨을 확인했다.
- API에서 실제 사용할 수 있는 사진 328개는 다운로드와 이미지 디코딩 검증을 통과했다. 사진이 없는 32곳은 기존 기본 이미지를 사용한다. 사진 유무로 유명 장소를 제외하거나 다른 장소의 사진을 붙이지 않는다.
- 실제 PostgreSQL 통합 검증: 전체 후보 수 360, `size=100`이면 100개, 18개 시군 각각 20개, 숨김·타지역·미선정 장소 제외.
- 프론트 검증: 20개 카드의 분류·상세 링크, 사진 없는 카드, 새로고침·재진입·지역 변경·재시도·좋아요 연동 및 오류 응답에 관한 회귀 테스트.

## API 동작

`GET /api/v1/spots/recommended?region=51&sigungu=150&size=20`

- `region` 기본값은 `51`, 빈 값도 `51`로 취급한다. 선택적 `sigungu`가 없으면 360곳 전체가 후보이며 다른 광역 지역/미지원 시군은 빈 목록이다.
- `size`는 1~100(기본 20)이다. **후보 수 360과 한 요청의 응답 상한 100은 별개**다. `totalCount`는 현재 조회 가능한 고유 후보 수이며 `offset=0`이다.
- 정확한 `title`·`sigungu`와 일치하는 활성 TourAPI 레코드를 선택한다. 환경별 DB ID를 선정 키로 하드코딩하지 않는다. 메타데이터의 `auditSpotId`는 운영 검수용이다.
- 동일 장소 중복 수집은 가장 작은 ID 하나로 정리하고, 카탈로그 밖/숨김/미수집 후보는 제외한다. 후보가 부족해도 일반 음식점 등으로 채우지 않는다.
- 매 요청 전체 후보를 섞은 뒤 요청한 수만 반환한다. 전체 화면은 360곳 중 20곳, 지역을 선택하면 해당 20곳을 섞어서 보여준다. 전체 추천에 모든 지역이 반드시 포함되거나 새로고침 결과가 반드시 달라진다는 보장은 없다.
- 좋아요와 사진은 기존 일괄 조회 경로를 사용한다. 카드 좋아요 변경은 추천 목록을 다시 추첨하지 않는다.
- 브라우저와 응답은 `no-store`. 기존 검색/인기순 목록과 전체보기 페이지는 기존 동작을 유지한다.
- 카탈로그가 누락되거나 잘못된 형식, 지원하지 않는 시군 코드, 중복, 360곳 초과이면 시작 시 실패한다.

## 재검수 및 게시

```sh
python scripts/publish-recommended-spots.py --bucket planfix-bucket-975050156432-ap-northeast-2-an
# boto3 및 AWS 표준 인증 설정 후 실행. 인증 정보는 저장소에 기록하지 않는다.
python scripts/publish-recommended-spots.py --bucket planfix-bucket-975050156432-ap-northeast-2-an --publish --report /tmp/recommended-s3-report.json
```

첫 명령은 로컬 형식·분포 검증만 수행한다. 새 데이터 게시 시 `--prefix catalogs/recommended-spots/새버전/`을 사용한다. 카탈로그와 출처 목록의 `(sigungu,title)` 순서까지 같아야 하며 모든 지역이 20개여야 한다. 장소 교체 전 공식 정보와 운영 API의 정확한 이름·지역·주소·좌표 및 중복 시설 여부를 다시 검토한다.
