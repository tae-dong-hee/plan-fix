# AI 코스의 자동차 도로거리 정렬

AI 또는 추천 규칙이 날짜별 장소를 고른 다음, 카카오 자동차 길찾기의 `priority=DISTANCE` 결과로 방문 순서를 다시 계산한다. 산과 하천을 우회하는 도로, 방향별 통행 차이는 길찾기 응답에 반영된다.

## 적용 범위

- 각 날짜에 이미 선택된 장소를 모두 한 번씩 방문하는 순서를 구한다. 장소 선정과 날짜 배분은 바꾸지 않는다.
- 별도 출발지·도착지·숙소 입력이 없으므로 시작과 끝은 자유이며, 출발지로 돌아오는 구간은 포함하지 않는다.
- 방향별 모든 구간을 조회한다. A→B와 B→A의 거리를 같은 값으로 취급하지 않는다.
- 하루 최대 10곳까지 조회된 도로거리 합계가 최소인 순서를 정확히 계산한다. 비용이 같으면 입력 인덱스의 사전순으로 결정하며, 기존 순서도 최단이면 그대로 유지한다.
- 이동시간·식사시간·영업시간·다음 날과의 연결은 최적화 대상이 아니다. 현재 지도 점선은 정렬된 방문 순서를 표시한다.

## 서버 설정

길찾기에 사용하도록 허용한 카카오 **REST API 키**를 서버의 `KAKAO_MOBILITY_REST_API_KEY` 환경변수로 지정한다. 브라우저의 JavaScript 지도 키로는 인증할 수 없다. 키를 프런트엔드 환경변수나 Git에 넣지 않는다.

키가 비어 있으면 외부 API를 호출하지 않는다. 기존 로그인용 키는 자동으로 재사용하지 않는다.

사용 API: `GET https://apis-navi.kakaomobility.com/v1/directions`, `priority=DISTANCE`, `summary=true`.

## 응답과 실패 처리

`days[]`에 다음 필드가 추가된다.

| 필드 | 값 |
| --- | --- |
| `routeStatus` | `ROAD_DISTANCE`: 도로거리 최적화 완료, `UNAVAILABLE`: 추천 순서 유지, `NOT_NEEDED`: 장소가 0~1곳 |
| `drivingDistanceMeters` | 선택한 순서의 도로거리 합계(m). 조회 실패 시 `null` |

인증 오류, 쿼터 초과, 시간 초과, 해석할 수 없는 응답은 직선거리로 대체하지 않는다. 해당 날짜의 추천 순서를 보존하고 화면에도 도로거리를 확인하지 못했다고 알린다. API에서 명시적으로 경로 없음(`result_code=1`)을 반환한 방향은 통행 불가로 처리한다. 다른 실패 코드는 거리 미확인으로 처리한다.

## 호출 제한

하루 n곳이면 최대 n(n−1)개 구간을 조회한다. 6곳은 30회다. 동시 요청은 서버 전체 4개, 대기열은 90개로 제한한다. 연결 2초·읽기 5초·날짜별 일괄 조회 20초 제한을 두고, 전체 코스에서 30초가 경과하면 남은 날짜는 추가 조회하지 않는다. 이미 시작한 날짜의 조회는 해당 날짜의 제한까지 진행될 수 있다.

성공한 방향별 거리는 10분 동안 최대 2,000개를 메모리에 보관한다. 실패 응답은 캐시하지 않는다. 여러 서버 인스턴스에서는 캐시와 동시 요청 제한이 인스턴스별로 적용된다.

## 검증

거리 행렬의 정확한 최단 순서, 일방통행, 통행 불가, 실패 시 순서 보존, AI/추천 규칙 공통 적용, API 인증 헤더·응답 해석·캐시·시간 제한을 모의 API로 검증한다. 실제 API 사용 가능 여부는 서버 키를 지정한 후 별도 확인이 필요하다.
