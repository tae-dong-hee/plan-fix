# 코스 초대·권한·카카오 공유 검증 (2026-09-21)

## 적용 정책

같은 코스의 한 사람은 멤버 레코드와 권한을 하나만 가진다. 기존 멤버가 더 새로 발급한 초대를
수락하면 해당 권한으로 갱신한다. 권한의 대소가 아니라 초대 발급 순서를 기준으로 한다.
이미 적용한 링크나 더 오래된 링크를 다시 수락해도 최신 권한이 되돌아가지 않는다.

| 검증한 동작 | 결과 |
| --- | --- |
| 편집 멤버가 더 새로운 읽기 초대 수락 | 읽기로 변경, 멤버 1명 유지, 실제 수정 API 거부 |
| 읽기 멤버가 더 새로운 편집 초대 수락 | 편집으로 변경, 실제 수정 API 허용 |
| 동일 링크 반복 / 과거 링크 재수락 | 최신 권한 유지, 중복 멤버 없음 |
| 오래된 링크와 새 링크를 역순·동시에 수락 | 더 최신 발급 링크의 권한 하나로 수렴 |
| 소유자가 멤버 관리에서 권한 변경 | 즉시 반영, 변경 전에 발급된 링크로 되돌릴 수 없음 |
| 소유자 변경 후 새로 발급된 초대 수락 | 새 초대 권한으로 갱신 가능 |
| 멤버 제거 후 예전 초대 재수락 | 거부, 제거 후 새로 발급한 초대 필요 |
| 초대 취소 | 해당 링크 무효, 기존 멤버 및 다른 사람의 권한 유지 |
| 비공개 전환 / 코스 삭제 | 기존 멤버의 쓰기 및 보호 데이터 접근 거부 |
| 최신 링크 취소 후 소유자 변경 / 과거 링크 재수락 | 권한 기준이 과거로 되돌아가지 않음 |
| 기존 데이터에 권한 순서가 없는 경우 | 기존 권한 보호, 새 초대부터 최신 권한 적용 |

링크 복사와 카카오 공유는 동일한 `/course-invites/{token}` 및 수락 API를 사용한다.
초대는 특정 수신자에게 묶이지 않은 7일 유효 다회 사용 링크다.

## 수정한 버그

- 늦은 멤버 목록 응답이 방금 변경·회수한 화면 상태를 덮어쓰는 문제.
- API 주소가 없는데 권한 변경·회수·초대 취소를 성공처럼 처리하던 문제.
- 코스 이동 후 이전 비동기 요청의 성공·오류가 새 코스 화면에 영향을 주는 문제.
- 인증 만료 처리와 중복 요청 방지, 변경 실패 시 기존 상태 보존 보완.
- 실제 멤버 권한과 초대 링크 권한을 혼동하기 쉬운 설명 보완.
- 카카오톡 전송 후 공유창에 완료 상태와 확인 버튼이 없던 문제.

## 검증 및 역검증

- 백엔드 전체: **96 suites / 699 tests**, 실패·오류·건너뜀 0.
- 프론트 전체: **60 files / 983 tests** 통과.
- VM 배포·롤백 테스트: **8개** 통과.
- 프론트 타입 검사·프로덕션 빌드·diff 공백 검사 통과.
- 권한 관련 단위·API 통합·동시성 3클래스: 57개.
- 동시성 검증은 별도 PostgreSQL 트랜잭션과 `pg_blocking_pids`로 실제 잠금 대기를 확인했다.
  수락↔수락, 수락↔소유자 변경, 수락↔회수의 양쪽 순서와 회수 후 숙소 쓰기를 검사했다.
- 화면 역검증은 초대 표시가 편집이어도 서버의 실제 권한이 읽기면 수정 UI를 노출하지 않는 경우,
  반대 경우에는 서버의 실제 편집 권한을 유지하는 경우를 포함한다.
- 별도 검토자가 생산 코드의 권한 우회·잠금·기존 데이터 초기화·화면 비동기 처리를 검토했고,
  머지를 막는 결함은 발견하지 못했다.
- 앞선 Chrome 360px/1280px 모의 전송 검증에서 전송 확인 후 완료 표시·확인으로 닫기를 확인했다.
  실제 카카오 채팅방 메시지는 보내지 않았다.

## 운영 준비

`course_members.last_applied_invite_id` nullable 컬럼과 `course_invite_kakao_shares` 테이블이 필요하다.
현재 운영의 `ddl-auto: update`는 두 스키마를 생성한다. 수동 DDL용 파일은 `docs/migrations/`에 있다.
기존 멤버 순서는 코스 잠금 안에서 안전하게 초기화하므로 별도 일괄 backfill은 필요하지 않다.

카카오 완료 확인에는 대표 어드민 키와 POST 공유 웹훅 설정이 필요하다.
설정·API 규격은 `course-invites-api.md`를 따른다. 실제 전송 완료와 초대 수락은 서로 별개다.
일반 링크 복사/다른 앱 공유만으로는 카카오 전송 완료를 확인하지 않는다.
