# 이메일 계정 복구 검증 기록

2026-09-19, 이메일 전용 변경과 `origin/main`의 `116a66a`를 합친 `556a835` 기준이다.
이전 문자 인증 초안의 테스트 개수는 사용하지 않는다.

## 자동 검증

- 백엔드 `./gradlew test bootJar --console=plain`: 89개 스위트, 628개 테스트 통과, 실패·오류·건너뜀 0.
- 프런트엔드 `npm run typecheck`, `npm test`, `npm run build`: 48개 파일, 759개 테스트 통과, 타입 검사·운영 빌드 성공.
- 398×844 모바일 화면에서 아이디 찾기, 비밀번호 찾기, 회원가입의 가로 넘침과 브라우저 실행 오류 없음.
- 최신 main의 카카오 즉시 로그인·개인정보·저장·초대 변경 보존 및 복구 링크 연결을 별도로 검토했다.

## 정상 흐름과 역검증

- 가입 이메일 → 아이디 안내 메일 → 아이디·이메일 확인 → 재설정 메일 → 새 비밀번호 로그인 연결.
- 이전 비밀번호 및 기존 JWT 세션 무효화, 재설정 토큰 해시 저장·30분 만료·1회 사용.
- 잘못된 아이디/이메일, 미가입·탈퇴·카카오 전용 계정, 누락·변조·만료·재사용 토큰 거절.
- SMTP 실패 시 성공 응답 방지, 커밋 후 SMTP 수락까지 응답 대기, 롤백 시 발송 방지.
- 재전송·시간당 발송·공유 연결 주소 한도, 동시 발송 1회, 동시 토큰 사용 1회, 실패 후 한도 유지.
- 다른 사람의 이메일을 변경한 뒤 복구하는 공격을 막는 사용자 PATCH/DELETE 소유권 검사.
- 이메일 local-part 대소문자가 다른 기존 계정 ID가 다른 수신함으로 합쳐져 나가지 않도록 검사.
- HTTP 응답에 아이디·토큰을 반환하지 않고 로그의 복구 요청·이벤트 민감값을 숨긴다.
- 문자 서비스·휴대폰 복구 UI/API 및 설정 의존성을 제거했다.

위 비밀번호 변경·세션 검증은 격리된 PostgreSQL 테스트 계정으로 수행했다. 실제 사용자 비밀번호는 변경하지 않았다.

SMTP 서버의 접수를 확인했다. 받은편지함 도착은 사용자 확인을 기다리는 중이며, 운영 배포 및 실제 복구 API 발송은 아직 검증하지 않았다.
