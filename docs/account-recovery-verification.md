## 정상·역검증 범위

- 가입 문자 인증 → 가입 증명 제출 → 번호 연결 → 아이디 확인 → 비밀번호 재설정.
- 기존 회원의 현재 비밀번호 확인 → 문자 인증 → 복구용 번호 등록·변경.
- 이메일 정상 일치, 틀린 아이디·이메일, 비활성·카카오 전용 계정 차단.
- 이메일 SMTP 접수 성공만 성공 응답, SMTP 거절·TLS 미지원·설정 누락의 실패 응답.
- 실제 loopback SMTP 소켓으로 envelope, UTF-8 본문, URL fragment 링크 확인.
- SOLAPI HMAC 요청, 공급자 정상 접수, HTTP 200 내부 실패, 잘못된 응답, 리디렉션·타임아웃 거절.
- 인증번호 오입력 횟수 보존, 다섯 번째 실패, 만료·재사용·이전 발급·다른 목적·다른 계정 차단.
- 이전 휴대폰번호와 중복 번호 등록 차단, 가입 실패 시 인증 증명도 함께 롤백.
- 새 비밀번호 로그인, 이전 비밀번호와 기존 세션 차단, 토큰 동시 사용 한 번만 성공.
- 동시 가입의 번호 유일성, DB 연결 3개에서 동시 요청 12개 처리.
- 타인 프로필의 복구 이메일 수정·탈퇴를 USER/ADMIN 모두 거절, 비로그인 요청 거절.
- MVC DEBUG 설명과 공급자 오류 로그에 인증번호·비밀번호·토큰·수신정보 미노출.
- UI의 만료·재전송 제한, 번호 변경 후 늦게 도착한 응답 무시, 공급자 장애의 가짜 성공 차단.

독립 코드 검토에서 발견한 트랜잭션의 이중 연결 점유와 프록시 주소 공유의 낮은 요청 한도를
수정한 뒤 다시 검증했다. 추가 확인된 타인 회원 정보 변경 문제도 소유자 검사로 차단했다.

로컬 Chrome의 398px 화면에서 로그인·가입·아이디 찾기·비밀번호 찾기 화면을 확인했다.
가로 넘침과 브라우저 실행 오류는 없었고, 빈 휴대폰번호 제출 시 입력 오류가 표시됐다.

## 외부 발송과 운영 상태

자동 검증에는 일회용 PostgreSQL, 로컬 SMTP 서버, 로컬 HTTP 문자 공급자 모형을 사용했다.
운영 회원의 비밀번호를 변경하거나 외부 메일·문자를 발송하지 않았다.

확인 당시 운영 Cloud Run과 Secret Manager에 SMTP·SOLAPI 발송 설정이 없고 로컬 SMTP
입력값도 비어 있었다. 기존 AWS 자격증명으로 SES 발신자 조회를 시도했으나 접근이 거절됐다.
따라서 **실제 메일·문자 수신 및 운영 전체 흐름 검증은 미완료**이다.

발신 계정·등록된 문자 발신번호·테스트 수신자를 [계정 복구 설정](account-recovery.md)에 따라
준비한 뒤 외부 수신, 링크·인증번호 확인, 새 비밀번호 로그인, 재사용 거절까지 추가 확인해야 한다.
이 기록은 운영 반영이나 실수신 검증의 완료를 의미하지 않는다.
