# 이메일 계정 복구 검증 기록

2026-09-20 운영 배포 커밋 `45f800c` 기준이다. 이메일 계정 복구 변경은 PR #83,
재요청 대기 시간 안내 수정은 PR #91에 포함됐다. 이전 문자 인증 초안의 테스트 개수는 사용하지 않는다.

## 자동 검증

- 백엔드 `./gradlew test bootJar --console=plain`: 89개 스위트, 628개 테스트 통과, 실패·오류·건너뜀 0.
- 프런트엔드 `npm run typecheck`, `npm test`, `npm run build`: 48개 파일, 759개 테스트 통과, 타입 검사·운영 빌드 성공.
- 398×844 모바일 화면에서 아이디 찾기, 비밀번호 찾기, 회원가입의 가로 넘침과 브라우저 실행 오류 없음.
- 최신 main의 카카오 즉시 로그인·개인정보·저장·초대 변경 보존 및 복구 링크 연결을 별도로 검토했다.
- 계정 복구 관련 격리 테스트 11개 스위트, 73개 테스트가 실패·오류·건너뜀 없이 통과했다.

## 정상 흐름과 역검증

- 가입 이메일 → 아이디 안내 메일 → 아이디·이메일 확인 → 재설정 메일 → 새 비밀번호 로그인 연결.
- 이전 비밀번호 및 기존 JWT 세션 무효화, 재설정 토큰 해시 저장·30분 만료·1회 사용.
- 잘못된 아이디/이메일, 미가입·탈퇴·카카오 전용 계정, 누락·변조·만료·재사용 토큰 거절.
- SMTP 실패 시 성공 응답 방지, 커밋 후 SMTP 수락까지 응답 대기, 롤백 시 발송 방지.
- 재전송·시간당 발송·공유 연결 주소 한도, 동시 발송 1회, 동시 토큰 사용 1회, 실패 후 한도 유지.
- 다른 사람의 이메일을 변경한 뒤 복구하는 공격을 막는 사용자 PATCH/DELETE 소유권 검사.
- 이메일 local-part 대소문자가 다른 기존 계정 ID가 다른 수신함으로 합쳐져 나가지 않도록 검사.
- HTTP 응답에 아이디·토큰을 반환하지 않고 로그의 복구 요청·이벤트 민감값을 숨긴다.
- 문자 서비스·휴대폰 복구 UI/API 및 설정 의존성을 제거했다.

만료·동시 요청·SMTP 실패와 같은 경계 조건은 격리된 PostgreSQL 및 SMTP 대역 테스트에서 확인했다.
실제 사용자 비밀번호는 변경하지 않았다.

## 실제 SMTP 확인

2026-09-20: 운영 서비스 `https://planfix.cloud`에서 Gmail 주소로 일회용 테스트 계정을 만들고
아이디 찾기 및 비밀번호 재설정 API를 호출했다. 네이버 SMTP가 보낸 두 안내 메일이 실제 Gmail
받은편지함에 도착했고, 아이디 안내 내용과 재설정 링크가 해당 테스트 계정과 일치했다.

수신한 링크가 운영 비밀번호 변경 화면을 열고 비밀번호 입력란을 활성화하며, 화면 로딩 후 토큰을
브라우저 주소에서 제거하는 것을 확인했다. 같은 수신 토큰으로 운영 API에서 새 비밀번호를 설정한 뒤
새 비밀번호 로그인에 성공했다. 이전 비밀번호와 기존 로그인 세션은 거부됐고, 사용한 링크의 재사용도
거부됐다. 이메일 불일치, 즉시 재전송, 잘못된 토큰과 약한 비밀번호도 각각 거부됐다.

검증 후 테스트 계정에서 Gmail 주소를 해제하고 탈퇴 처리했다. 탈퇴 계정은 로그인할 수 없고 해당
Gmail 주소를 다시 회원가입에 사용할 수 있음을 확인했다. 브라우저에서는 수신 링크로 변경 화면이
열리는 단계까지 확인했으며, 비밀번호 입력과 제출은 운영 API로 검증했다.

자격증명은 이 문서에 기록하지 않는다.
