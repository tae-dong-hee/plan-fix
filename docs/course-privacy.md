# 코스 공개 범위

`PRIVATE`는 작성자만 접근하는 **나만 보기**, `PUBLIC`은 누구나 조회하는 **전체 공개**입니다. 초대 멤버는 공개 코스에만 참여할 수 있고, 공개 범위 변경은 작성자만 할 수 있습니다.

| 동작 | 나만 보기 | 전체 공개 |
| --- | --- | --- |
| 상세·일정·메모 조회 | 작성자만 | 누구나 |
| 내 코스 목록 | 작성자만 | 작성자와 참여 멤버 |
| 공개 목록 | 제외 | 포함 |
| 좋아요·위시리스트 | 작성자만 | 로그인 사용자 |
| 친구 초대·초대 미리보기·수락 | 불가 | 가능 |
| 여행 이야기의 코스 연결 | 불가 | 작성자만 연결 가능 |
| 코스 내용 수정 | 작성자만 | 작성자와 EDITOR |
| 공개 범위 변경 | 작성자만 | 작성자만 |

작성자가 나만 보기로 저장하면 한 트랜잭션 안에서 멤버와 초대 링크를 삭제하고, 다른 사용자의 좋아요를 삭제한 뒤 좋아요 수를 다시 계산합니다. 작성자의 좋아요는 유지합니다. 기존 여행 이야기에서는 코스 연결만 해제하고, 별도로 발행한 이야기 본문은 유지합니다. 이후 다시 전체 공개로 변경해도 해제된 초대·권한·좋아요·이야기 연결은 자동 복원하지 않습니다.

기존 비공개 데이터에 멤버·좋아요·초대가 남아 있어도 각 조회·수정 경로에서 접근을 차단합니다. 해당 코스를 저장하거나 다시 공개할 때 남아 있는 공유 데이터도 정리하므로 과거 권한이 되살아나지 않습니다.

여행 이야기를 생성하거나 수정할 때 비공개 코스를 연결하면 HTTP 400과 공개 전환 안내를 반환합니다. 코스를 자동으로 공개로 바꾸지 않습니다. 비공개 초대 링크의 미리보기·수락은 코스 제목 없이 일반 HTTP 404로 응답합니다. 권한 없는 상세·좋아요·수정·숙소 조회는 HTTP 403으로 응답합니다.

비공개 전환, 초대 생성·수락·취소, 멤버 권한 변경·삭제, 좋아요 및 이야기 연결은 같은 코스 행의 비관적 쓰기 잠금을 사용합니다. 초대 수락은 잠금을 얻은 뒤 토큰을 다시 확인하므로 전환 중 폐기된 링크로 멤버십을 복구할 수 없습니다.

## 수정 충돌과 멤버 제거

HTTP 코스 수정 요청은 조회 응답의 `updatedAt` 문자열을 `expectedUpdatedAt`으로 전달해야 합니다. 코스 잠금 안에서 값이 다르거나 누락되면 409로 거절합니다. 화면은 저장을 중단하고 사용자가 최신 코스를 다시 불러오도록 안내합니다. 사용자가 공개 범위를 바꾸지 않은 수정은 `visibility`를 보내지 않습니다. 시간 정밀도는 PostgreSQL과 같은 마이크로초로 저장하여 정상 요청이 충돌하는 일을 막습니다.

공개 코스의 멤버를 제거하면 해당 사용자에게 제거 당시까지 발급된 초대를 무효화합니다. 다른 사용자는 같은 링크를 계속 사용할 수 있으며, 제거된 사용자는 작성자가 이후 발급한 새 링크로만 다시 참여할 수 있습니다. 이 기준은 `course_member_revocations` 테이블에 저장합니다. 운영의 Hibernate `ddl-auto: update`가 테이블을 생성하며, 자동 DDL을 사용하지 않는 환경은 [마이그레이션 SQL](migrations/2026-09-19-course-member-revocations.sql)을 먼저 적용해야 합니다.

응답의 `canEdit`은 작성자 및 공개 코스의 편집 멤버에게만 참입니다. 편집자는 일정 수정 화면에 접근하지만, 작성자 전용인 숙소와 공개 범위는 변경하지 않습니다. 숙소 조회 실패 시 저장을 막아 빈 값으로 덮어쓰지 않습니다. 코스 저장 후 숙소만 실패하면 부분 성공을 알리고 기존 코스 ID와 수정 시각을 유지하여 재시도·임시저장 복원 시 중복 생성하지 않습니다.

401만 로그인으로 안내하고, 403은 접근 권한 변경으로 안내합니다. 상세와 위시리스트는 탭 복귀 시 다시 조회하고, 접근이 차단되거나 목록에서 제외된 코스는 화면에서 지웁니다. 이미 전달된 데이터의 회수나 실시간 강제 삭제를 보장하는 방식은 아닙니다.

## 검증

실행에는 Java 21과 Docker가 필요합니다. Spring 테스트는 기존 Testcontainers 설정의 임시 PostgreSQL을 사용하며 운영 DB로 연결하지 않습니다.

```sh
cd backend
./gradlew test

cd ../frontend
npm test
npm run typecheck
npm run build
```

주요 회귀 테스트:

- `CoursePrivacyIntegrationTest`: 실제 쿠키 인증과 DB로 사용자별 조회, 기존 데이터 우회, 좋아요 제거, 초대 해제, 자동 공개 금지, 실패 시 원자성, 오래된 저장 거절, DB 시간 정밀도, 멤버 제거 후 초대 재사용 차단을 검증합니다.
- `CoursePrivacyConcurrencyTest`: PostgreSQL의 실제 잠금 대기를 관찰하며 초대 수락과 비공개 전환이 겹쳐도 권한이 남지 않는지 검증합니다.
- `CourseInviteApplicationServiceTest`: 비공개 초대 차단, 공개 초대 유지, 잠금 대기 중 폐기된 토큰 재사용 차단을 검증합니다.
- 생성·수정·상세·여행 후기 화면과 서비스 테스트: 비공개 초대 숨김, 비공개 이야기 연결 차단, 공개 전환 안내와 API 오류 전달을 검증합니다.
