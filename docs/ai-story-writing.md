# 사진으로 여행 이야기 작성

`/boards/create`에서 **AI로 작성 / 직접 작성**을 선택합니다. AI 작성에서 여행 사진을 고르면 사진 내용을 분석해 본문을 자동으로 채웁니다. 선택 메모로 장소나 함께 담고 싶은 기억을 전달할 수 있습니다. 제목은 사용자가 직접 작성합니다.

- JPG·PNG·WebP 1~6장, 장당 5 MiB, 전체 15 MiB까지 지원합니다.
- 생성한 본문은 기존 에디터에서 수정할 수 있습니다. 기존 글이 있거나 생성 중 본문을 수정하면 새 초안을 별도로 보여주고, 뒤에 추가하거나 본문을 교체할 수 있습니다. 제목이 바뀌면 이전 제목의 결과와 대기 중인 초안을 적용하지 않고, 새 제목으로 다시 쓰도록 안내합니다.
- 게시글에 연결할 코스는 내가 소유한 코스만 표시합니다. 코스를 연결한 뒤 실제로 다녀온 장소만 선택하며, 장소 선택과 직접 겪은 일의 메모를 사진보다 먼저 입력할 수 있습니다.
- 직접 작성으로 전환해도 본문과 선택 사진을 유지합니다. 생성 중 직접 작성으로 전환하면 늦게 도착한 결과를 적용하지 않습니다.
- 사진은 발행 시 기존 이미지 업로드 API로 저장되고 게시글 사진 목록에 포함됩니다. 별도 커버가 없으면 첫 번째 선택 사진을 커버로 사용합니다. 발행 실패 후 재시도할 때 이미 업로드한 사진 URL을 재사용합니다. 본문에 넣는 사진의 업로드가 끝날 때까지 발행을 기다리며, 발행 시 에디터의 현재 본문과 사진을 함께 저장합니다.

## API와 설정

인증된 `POST /api/v1/boards/ai-draft` 요청에 multipart `files`를 반복해 전달하고, 선택적으로 `title`(100자 이하), `note`(500자 이하), `courseId`, 반복된 `visitedSpotIds`를 보냅니다. 코스와 장소 ID는 양의 정수이며, 방문 장소는 중복 없이 최대 20곳입니다. 방문 장소를 보낼 때는 `courseId`가 필요하고 해당 코스에 포함된 장소만 사용할 수 있습니다. 응답은 `{ "content": "일반 텍스트 본문" }`입니다. 이 API는 게시글이나 사진을 저장하지 않습니다.

서버는 `CourseApplicationService.getCourse`의 소유자·멤버·공개 코스 조회 권한을 검사하고 선택한 장소 이름을 서버 데이터에서 가져옵니다. 조회할 수 없는 코스는 기존 403/404 오류를 반환합니다. 코스를 연결해도 사용자가 방문했다고 선택하지 않은 장소, 코스의 날짜·메모·계획 순서는 모델에 전달하지 않습니다. 잘못된 장소 선택은 모델 호출 전에 400 오류로 거절합니다.

작성 지침은 약 150~350자, 1~3개 짧은 문단의 담백한 일상 말투를 요청하며, 정보가 적으면 짧게 끝냅니다. 사용자가 적은 구체적인 경험과 아쉬웠던 점을 우선 보존하고, 사진마다 풍경을 나열하거나 과장된 수식어를 반복하지 않습니다. 장소명은 제목·메모와 사용자가 방문을 확인한 장소에 한정하며 사진에서 추측하지 않습니다. 확인한 장소와 사진/활동의 관계도 임의로 연결하지 않습니다. 예를 들어 강촌레일파크 방문과 레일바이크 탑승이 각각 입력되어도 탑승 장소가 메모에 명시되지 않았다면 별개의 문장으로 씁니다. 사용자 경험이 없는 사진은 눈에 보이는 특징만 중립적으로 적고 맛·감정·사진 촬영 행위까지 만들어내지 않습니다.

초안 생성(temperature 0.7) 후 같은 제목·메모·확인 장소·사진으로 사실 검토(temperature 0.2)를 한 번 더 수행합니다. 초안은 확인된 사실이 아닌 검토 대상으로 전달하며, 검토된 본문만 사용자에게 반환합니다. 두 응답 모두 누락·공백·길이 초과·잘린 출력·콘텐츠 필터·HTML·코드블록 여부를 검사합니다. 검토가 실패하면 확인되지 않은 첫 초안으로 대체하지 않고 다시 시도하거나 직접 작성할 수 있는 503 오류를 반환합니다. 모델의 검토가 사실성을 보장하지는 않으므로 완성된 본문은 사용자가 확인하고 편집할 수 있습니다.

기존 `GEMINI_API_KEY`, `GEMINI_MODEL`을 사용합니다. 사진 작성 전용 모델은 단계마다 35초의 응답 기한을 적용하며 자동 재시도하지 않습니다. 한 사용자 요청은 최대 두 번의 모델 호출(총 70초)로 제한하고, 브라우저는 90초 후 재시도 안내를 표시합니다. API가 준비되지 않았거나 생성·검토에 실패하면 오류를 반환하며 임의의 여행담으로 대체하지 않습니다. 코스 생성 모델의 설정은 별도로 유지합니다. 본문은 HTML 문자열 대신 에디터의 텍스트 노드로 삽입합니다.

서버는 파일 서명·실제 이미지 디코딩·해상도·용량을 검사하고, 사진을 최대 1280px JPEG로 변환하여 Gemini에 전달합니다. 두 단계는 동일하게 준비한 사진을 사용합니다. 원본 사진과 메모, 모델 요청/응답은 로그에 기록하지 않습니다. 서버 인스턴스마다 사용자별 동시 요청 1개, 시간당 10회, 전체 동시 요청 4개로 제한합니다. 초안과 검토는 하나의 동시 실행 슬롯을 공유하며 시간당 사용량도 사용자 요청 한 번으로 계산합니다. 어느 단계에서 실패해도 슬롯을 반납합니다.

## 확인

```sh
cd frontend
npm run typecheck
npm test
npm run build
```

Java 21에서 백엔드 테스트로 멀티모달 요청과 두 단계의 컨텍스트·온도, 검토 결과만 반환하는지, 단계별 잘못된 응답과 실패 후 슬롯 반납, 응답 기한, 방문 장소 컨텍스트·코스 접근 권한 오류·ID 검증, 이미지 검증, 호출 제한, 인증을 확인합니다. 자동 테스트는 실제 Gemini와 운영 DB를 호출하지 않습니다.
