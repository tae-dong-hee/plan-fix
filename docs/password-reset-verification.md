# 비밀번호 재설정 검증 기록

이 문서는 2026-09-19 커밋 `a8c1863` 기준의 **이전 구현 검증 기록**이다.
현재 계정 복구 기능과 검증 범위는 [계정 복구 안내](account-recovery.md)를 참고한다.
현재 구현은 정보 불일치 `400`, 재요청 제한 `429`, SMTP 실패 `503`으로 응답하며
아래 당시의 균일 응답 동작과 다르다. 실제 외부 발송 검증이 완료됐다는 기록은 아니다.

## 운영 환경에서 확인한 내용

- GitHub의 프런트엔드·백엔드 배포 성공을 확인했다.
- 검증 당시 Cloud Run 리비전 `planfix-backend-00018-d6p`가 해당 커밋 이미지로 트래픽 100%를 처리했다.
- 운영 서버·Secret Manager·프로젝트 로컬 비밀 설정에 SMTP 설정은 없었다.
- 메일 요청 API는 미설정 상태에서 `503 Service Unavailable`을 반환한다.
- 토큰 누락, 잘못된 형식, 정상 형식의 미등록 토큰은 각각
  `400 INVALID_PASSWORD_RESET_TOKEN`으로 거부된다.
- 두 API의 CORS preflight는 `https://planfix.cloud`와 credential 요청을 허용한다.

운영 계정의 비밀번호를 변경하지 않는 요청으로 위 결과를 확인했다.

## 자동 검증

```sh
cd backend
./gradlew test --tests '*PasswordReset*' --console=plain
```

비밀번호 재설정 관련 테스트 23개가 모두 통과했다. 테스트는 일회용 PostgreSQL과 로컬 SMTP
서버를 사용한다.

| 범위 | 검증 내용 |
| --- | --- |
| 정상 재설정 | 해시 토큰 저장, 30분 유효기간, 새 비밀번호 로그인, 이전 비밀번호 거부 |
| 세션 | 기존 토큰·이전 형식 JWT 무효화, 새 로그인 성공 |
| 토큰 | 누락·변조·미등록·만료·사용·이전 발급 토큰 거부, 동시 사용 시 1회 성공 |
| 계정 | 미등록·이메일 불일치·탈퇴·자체 인증정보 없는 계정 차단 |
| 변경 후 상태 | 발급 후 탈퇴하거나 자체 인증정보가 삭제된 계정 차단 |
| 트랜잭션 | 변경 롤백 시 이전 비밀번호·토큰 유지, 요청 롤백 시 메일 미발송 |
| SMTP 실패 | 기존 비밀번호·세션·발급 토큰 보존, 60초 제한, 복구 후 재요청 |
| 설정 오류 | 메일 제공자 누락, 호스트·발신 주소 오류, 잘못된 프런트엔드 URL, 헤더 주입 차단 |
| 실제 SMTP 프로토콜 | loopback 소켓에서 발신·수신 envelope, MIME 한글 UTF-8, 고정 출처의 fragment 링크 |
| SMTP 거절 | DATA 이후 554 거절 시 민감한 서버 응답·수신 주소·토큰을 로그에 남기지 않음 |
| TLS 역검증 | STARTTLS 필수인데 서버가 미지원이면 MAIL/RCPT/DATA 전에 차단, 평문 재시도 없음 |

## 운영 검증 완료

2026-09-20 운영 환경에 SMTP 설정을 적용하고 Gmail 수신까지 확인했다. 일회용 테스트 계정으로
아이디 찾기와 비밀번호 재설정 메일을 실제로 받은 뒤, 수신 링크·새 비밀번호 로그인·이전 비밀번호와
기존 세션 차단·링크 재사용 차단을 검증했다. 상세 결과는
[이메일 계정 복구 검증 기록](account-recovery-verification.md)에 있다.

검증용 계정은 이메일을 해제한 뒤 탈퇴 처리했으며 Gmail 주소가 다시 사용 가능한 상태임을 확인했다.
비밀번호·API 키·재설정 토큰은 문서나 Git에 기록하지 않는다.

현재는 실제 계정에만 SMTP 작업이 있어 요청 응답시간이 달라질 수 있다. 동일한 상태·본문 응답은
검증했지만 응답시간을 통한 가입정보 일치 여부 추정을 막는다고 보장하지 않는다.
